# Bulk Import and Export

## Workflow
Upload → bounded background parser → normalize and validate candidate → detect conflicts → stage rows in SQLite → ready/failed preview → explicit operator commit → compile one candidate → one transaction/revision → ArcSwap → report. Upload is the dry-run operation; no separate automatic publish endpoint exists. Import workers default to two; active jobs default to at most 100. No snapshot is compiled per record. Ready staging survives restart; interrupted pending/validating jobs fail visibly. Cancel removes staging, and retention cleanup expires old staging after 72 hours.

Default limits: file 64 MiB, 50,000 records, 64 KiB record, 256 MiB expanded XLSX. JSON nesting 48 levels. XLSX ZIP entry count 512 and bounded entry decompression are checked before calamine reads the workbook. Parsed documents are held in bounded memory for one worker; this is not a constant-memory SAX importer. Size workers × max_upload/expanded limits for available RAM.

## CSV
UTF-8 header row. Required `external_id,mapping_key`. Basic additional columns: source_host (semicolon-separated hosts), source_path, path_type (exact/prefix/template), enabled, priority, name, default_action_type (redirect/reverse_proxy), default_target_url, default_upstream_name, condition_json (array of complete MappingRule objects). Export additionally writes mapping_json and schema_version to preserve nested fields. A nonempty mapping_json is the complete Mapping record; external_id replaces its id.

Basic example:
```csv
external_id,mapping_key,source_host,source_path,default_target_url
example-001,QR001,abc.example.com,/QR001,https://example.org/
```

CSV exports embed complete mapping JSON so rules/paths/methods round-trip; upstream dependencies referenced by ID must already exist in the receiving draft. Formula-leading values are prefixed with apostrophe for spreadsheet safety; this may change display text when reimporting flat external columns. Prefer JSON/XLSX for lossless entity interchange.

## XLSX
Mappings sheet uses CSV-style headers with mapping_json preserving complete matcher/action metadata. Rules sheet has mapping_external_id, rule_id, rule_name, priority, enabled, condition_json, action_json; export omits nested rules from mapping_json so rules are linked once. Negative priorities are text cells, not formulas.

Optional Upstreams and Domains sheets contain `external_id,data_json`. Stable IDs in JSON must match external_id. Dependencies are read before mappings, so upstream names can resolve on the first import. Export writes all four sheets and preserves nested rule relationships and dependency JSON. Missing Mappings/header or unknown parent IDs produce errors. Excel formulas are never evaluated; output uses explicit string cells.

## JSON
Full nested document: `{domains:[],upstreams:[],mappings:[Mapping]}`; domains/upstreams optional. Mapping schema is in API_CONTRACT.md. JSON best preserves exact source URLs and complete entity values. Use schema_version=1 configuration representation where present; condition_schema_version=1 on rules.

## Policies and concurrency
reject fails on existing IDs. skip keeps existing records. upsert replaces complete entities under stable IDs, preserving existing mapping created_at. Duplicate IDs/keys within a file fail even under upsert. A mapping key owned by another ID fails; no silent reassignment. Route conflicts are detected by the same snapshot compiler used in production.

The job records SQLite committed revision and draft_generation at preview. Commit requires both unchanged, expected_revision, same policy, confirmation=true and Idempotency-Key. Stale jobs must be uploaded/validated again. Transaction commit records the idempotent result, new revision and draft in one step. Crash after SQL commit is recovered from the committed revision. The application compiles once per validation and once again at explicit commit to ensure integrity of the candidate; it does not compile per row.

## Errors and samples
CSV parser errors use row numbers; XLSX parser errors use sheet/row. Semantic errors identify the stable mapping external_id, and JSON semantic errors use /mappings/<index>. All individual records are validated without building a snapshot per row. JSON malformed documents produce a file error. Configuration-wide route errors are reported as candidate errors rather than falsely assigning them to a single row. Download `/imports/{id}/errors?format=csv` for the full report. Preview is paginated.

Templates are generated by the actual exporter. `cargo run -p proxy-import --example generate_samples` regenerates basic fixtures. Advanced conditional examples are provided in examples/import and tests/fixtures. No import is active until an authenticated operator commits it.

Upload buffering has a separate semaphore, acquired before multipart file bytes are read. Its capacity equals the configured import worker count. At most that many uploads and that many parser jobs can hold file buffers concurrently; excess requests receive 429.
